# 실험 프로토콜 및 재현성

본 문서는 명세서(평가 프로토콜·재현성 조건)에 따라 **(1) 데이터 구성·분할 방식, (2) 지표 정의·계산식, (3) 재현용 시드·설정값, (4) 베이스라인 정의**를 정리한다. 모든 성능 리포트(검색·추천·A/B)는 이 프로토콜을 기준으로 산출되었다.

---

## 1. 데이터 구성

고객 행동 시뮬레이터(`prepare_hm_data.py`)가 H&M Personalized Fashion Recommendations 데이터로 파라미터를 교정하여 생성한다.

| 항목 | 규모 |
|---|---|
| 상품 | 50,000건 (이미지·텍스트 메타 포함) |
| 사용자 | 10,000명 |
| 행동 로그 | 약 578만 건 (train 4,620,344 / valid 577,543 / test 577,544) |
| 카테고리 | 3단계 계층 — L1(5) → L2(10) → L3(15) |
| 이벤트 유형 | `search`, `view`, `cart`, `purchase` |

**6가지 페르소나** (`config.yaml`, 비율 합 1.0): 트렌드세터(0.15) · 실용주의자(0.25) · 가성비추구(0.25) · 브랜드충성(0.15) · 충동구매(0.10) · 신중탐색(0.10). 페르소나마다 선호 카테고리(`cat_L3_pool`) · 가격대(`price_tiers`) · 전환율(`view_to_cart`, `cart_to_purchase`)이 차별화되어 있다.

| 페르소나 | 선호 카테고리(L3) | 선호 가격대 | view→cart |
|---|---|---|---|
| 트렌드세터 | Garment Upper body | high | 0.15 |
| 실용주의자 | Underwear, Socks & Tights | low, medium | 0.08 |
| 가성비추구 | Garment Upper body | low | 0.10 |
| 브랜드충성 | Garment Full/Lower body | high | 0.12 |
| 충동구매 | Accessories, Swimwear | low, medium | 0.20 |
| 신중탐색 | Shoes, Nightwear | high, medium | 0.05 |

행동 로그는 3가지 퍼널로 생성된다: **success**(view→cart→purchase 연쇄) · **bounced_view**(이탈 조회) · **abandoned_cart**(장바구니 이탈). 시뮬레이터 설정(페르소나 비율·전이 확률·풀 크기 등)은 모두 `config.yaml` 로 변경 가능하다.

## 2. 데이터 분할 방식

**시간 기반 8 : 1 : 1 분할** — 최근 데이터를 test 로 배정하여 미래 정보 누수를 방지한다.

| 분할 | 비율 | 용도 |
|---|---|---|
| `train_logs.csv` | 80% (앞 시간대) | 모델 학습 + cross/context 피처 lookup 구성 |
| `valid_logs.csv` | 10% (중간 시간대) | 학습 중 검증 (조기 종료·베스트 모델 선택) |
| `test_logs.csv` | 10% (최근 시간대) | **평가 전용** — 모든 지표는 test_logs 만 사용 |

전체 기간 2024-01-01 ~ 2024-12-31, train 종료 시점 약 2024-10-18.
cross/context 피처(예: user-product 과거 카운트)는 **train_logs 만으로** 구성하여 평가 시 누수를 차단한다.

## 3. 재현용 시드 및 주요 설정값

**`random_seed = 42`** — 시뮬레이터 데이터 생성, 데이터 분할, 평가 샘플링, 모델 학습에 동일 시드 사용.

### 시뮬레이터 (`prepare_hm_data.py`)
| 파라미터 | 값 | 의미 |
|---|---|---|
| POOL_MIN / POOL_MAX | 60 / 200 | 유저별 상품 풀 크기 |
| CORE_RATIO | 0.25 | 풀 중 core(단골) 상품 비중 |
| P_CORE (페르소나별) | 0.25 ~ 0.55 | core 상품 선택 확률 (페르소나 전환 패턴 차별화) |
| ZIPF_CORE_ALPHA / POOL_ALPHA | 1.1 / 0.5 | core·pool 내 rank 기반 Zipf 분포 지수 |
| 활동량 버킷 | low 5–20 / mid 20–60 / high 60–200 | 유저별 행동 수 (비율 30/40/30) |

### Stage 1 — Two-Tower (`phase2_two_tower.py`)
| 항목 | 값 |
|---|---|
| User Tower 입력 | user_id 임베딩 + persona + cat_L1 선호분포 + price_tier 선호분포 + activity + 세션 GRU(최근 10행동) |
| Item Tower 입력 | item_id + category_L1/L2/L3 + price_tier |
| 차원 | USER_DIM 64 / ITEM_DIM 64 / SIDE_DIM 16 / OUT_DIM 64 |
| 학습 | in-batch softmax + logQ correction, EPOCHS 12 |
| 출력 | `two_tower.pth`, `item_embeddings.npy`, FAISS `candidate_item.index` |

### Stage 2 — DeepFM (`phase2_deepfm.py`)
| 항목 | 값 |
|---|---|
| Sparse 피처 15개 | user_id, product_id, persona, category_L1/L2/L3, price_tier (기본 7) + user_pid_prev, user_activity, cat3_match, tier_match, hour_bin, dow_weekend (Cross/Context 6) + pid_popularity, user_cat3_view (2) |
| 구조 | Embedding(dim 24) → FM 2차 상호작용 + Linear + DNN(MLP 128→64→1, Dropout 0.3) |
| 학습 | EPOCHS 15, Adam |

### 검색 — CLIP + FAISS (`phase1_embedding.py`)
| 항목 | 값 |
|---|---|
| 인코더 | CLIP `openai/clip-vit-base-patch32` (임베딩 512차원, L2 정규화) |
| 인덱스 | FAISS `IndexHNSWFlat` (M=32) — `text.index`(상품명 텍스트), `image.index`(상품 이미지) 각 50,000 |

## 4. 네거티브 샘플링 (명세 규격)

| 모델 | Positive | Negative | 비율 |
|---|---|---|---|
| Stage 1 Two-Tower | cart/purchase 상호작용 | in-batch 네거티브 + hard/random 네거티브 (logQ 보정) | 1 : 4 |
| Stage 2 DeepFM | cart/purchase (label=1) | bounced view = **노출 후 비클릭 implicit negative** + random negative | 1 : 4 |

## 5. 지표 정의 및 계산식

평가 샘플은 `test_logs.csv` 의 `purchase` 이벤트에서 `random_state=42` 로 추출한다 (검색 500건, 추천 500건, Coverage 1,000명).

| 지표 | 정의 | 계산식 |
|---|---|---|
| **MRR** | 검색 결과에서 정답 상품의 역순위 평균 | `MRR = (1/N) Σ 1/rank_i` (정답이 top-k 밖이면 0) |
| **NDCG@k** | 정답 순위를 로그 할인 (정답 1개 → IDCG=1) | `NDCG@k = (1/N) Σ [ 1/log₂(rank_i+1) if rank_i ≤ k else 0 ]` |
| **Recall@300** | 정답이 Stage 1 후보 300개 안에 포함된 비율 | `Recall@300 = (#{정답 ∈ Two-Tower 후보 top-300}) / N` |
| **AUC** | DeepFM 이 클릭(cart/purchase) vs 비클릭을 구분하는 능력 | `AUC = ROC-AUC(label, DeepFM 예측확률)`, label: cart/purchase=1, view+random neg=0 |
| **HitRate@50** | 정답이 최종 추천 Top-50 안에 포함된 비율 | `HitRate@50 = (#{정답 ∈ 최종 Top-50}) / N` |
| **NDCG@50** | 최종 추천 Top-50 내 정답 순위의 로그 할인 평균 | `NDCG@50 = (1/N) Σ [ 1/log₂(rank_i+1) if rank_i ≤ 50 else 0 ]` |
| **Coverage** | 추천된 고유 상품의 카탈로그 커버리지 | `Coverage = |⋃ 유저별 Top-50| / 50,000` |

검색 k=10, 추천 k=50 기준. 평가 스크립트: `phase4_offline_eval.py` → `data/metrics.json`.

### 응답 시간 측정 조건
warm-up 10회 후 단건(single request) 호출의 p95 기준, 최소 사양(CPU 4코어/RAM 16GB)에서 측정. CPU 전용 환경 ±50ms 허용.

## 6. 베이스라인 정의 (명세 규격)

각 리포트의 "베이스라인 대비 개선율"은 아래 베이스라인을 **동일 평가셋·동일 시드**로 실측하여 산출한다.

| 영역 | 베이스라인 | 구현 |
|---|---|---|
| 검색 | **BM25** 텍스트 단독 검색 | 상품명 토큰 기반 BM25 (k1=1.5, b=0.75), 역색인 |
| 추천 | **Two-Tower 단독** (랭킹 없이 후보만) | Stage 1 만 사용, FAISS Top-50 |
| 추천 | **인기도 기반** 추천 | train 의 purchase 상위 50개를 전 유저에 동일 추천 |

베이스라인 실측값과 본 시스템 대비 개선율은 `docs/02·03` 에 표로 제시한다.
